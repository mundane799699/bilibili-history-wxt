# 数据导出与备份提醒弹窗设计方案（评审稿）

> 状态：Implemented，待手工验收
>
> 目标版本：待定
>
> 本文同时作为实现说明与验收依据。

## 1. 结论

在主页面增加“数据导出与备份提醒”弹窗，明确告知用户：扩展数据主要保存在当前浏览器本地，浏览器数据清理、扩展卸载或重装、浏览器异常以及设备故障等情况都可能造成不可恢复的数据丢失。

弹窗不把数据丢失直接归因于浏览器自动清理，也不承诺本地存储保护可以完全避免丢失。它的主要作用是完成风险告知，并把用户引导到现有 `/webdav-sync` 页面，通过以下任一方式建立浏览器之外的备份：

- 手动导出完整 JSON 文件。
- 配置 WebDAV 手动备份。
- 配置 WebDAV 自动同步。

弹窗采用定期提醒而不是永久只显示一次，同时根据存储健康状态提高异常情况下的提醒优先级。

## 2. 背景与现状

近期用户多次反馈历史记录丢失，但当前没有足够证据确认唯一原因是浏览器自动清理。现有代码已经具备以下保护和备份能力：

- manifest 已声明 `unlimitedStorage` 权限。
- 主页面启动时会调用 `checkStorageHealth(true)`，检查扩展存储保护、持久化状态、容量和存储异常。
- 设置页已经展示本地存储健康状态，并在异常时建议导出 JSON 或配置 WebDAV。
- 设置页支持单独导出、导入历史记录和喜欢的音乐。
- WebDAV 页面支持导出全部数据为单个 JSON 文件。
- WebDAV 页面支持手动备份、恢复、双向同步和自动同步。

现有问题是这些能力主要依赖用户主动进入设置或 WebDAV 页面。大多数用户不会在数据丢失前主动寻找备份入口，因此需要在主界面增加显式提醒。

## 3. 目标与非目标

### 3.1 目标

- 明确说明本地数据存在丢失风险。
- 明确说明扩展作者无法访问或恢复没有备份的本地数据。
- 给出可以立即执行的备份入口，而不是只展示警告。
- 定期提醒尚未建立近期备份的用户。
- 存储未受保护或出现写入异常时，提高提醒优先级。
- 避免与现有版本更新弹窗同时显示。
- 适配明暗主题、键盘操作和窄屏布局。

### 3.2 非目标

- 不在本次弹窗功能中定位或修复历史记录丢失的根因。
- 不宣称浏览器自动清理是已经确认的原因。
- 不保证 `unlimitedStorage` 或持久化存储可以代替备份。
- 不在弹窗中重新实现 WebDAV 配置、导入或完整的数据管理界面。
- 不把自建云同步作为主要恢复方案；当前云同步页面尚未实现从云端下载数据。
- 不使用威胁、责怪或与用户对抗的文案。

## 4. 弹窗交互设计

### 4.1 默认状态

弹窗在主页面居中显示，使用琥珀色警告图标，视觉上表达“需要注意”，但不使用大面积红色，避免让用户误以为数据已经丢失。

建议布局：

```text
┌────────────────────────────────────────┐
│  ⚠  请及时备份你的数据             ×  │
│                                        │
│  历史记录保存在当前浏览器的本地存储中。│
│  清理浏览器数据、卸载或重装扩展、浏览器│
│  异常、设备故障等情况，都可能导致数据永│
│  久丢失。                              │
│                                        │
│  扩展作者无法访问或恢复未备份的本地数据。│
│                                        │
│  ┌──────────────────────────────────┐  │
│  │ 建议：现在导出完整 JSON，或配置  │  │
│  │ WebDAV 自动备份。                 │  │
│  └──────────────────────────────────┘  │
│                                        │
│               [我已了解] [立即备份]   │
└────────────────────────────────────────┘
```

### 4.2 建议文案

标题：

> 请及时备份你的数据

正文：

> 历史记录保存在当前浏览器的本地存储中。清理浏览器数据、卸载或重装扩展、浏览器异常、设备故障等情况，都可能导致数据永久丢失。
>
> 扩展作者无法访问或恢复未备份的本地数据，请定期导出 JSON 文件，或配置 WebDAV 自动备份。

提示卡片：

> 建议：重要数据至少保留一份浏览器之外的备份。

文案要求：

- 使用“可能导致”，不把尚未确认的原因表述为事实。
- 使用“无法访问或恢复未备份的本地数据”，明确能力边界。
- 不使用“丢了别来找我”“后果自负”等对抗性表达。
- 不暗示关闭弹窗等于已经完成备份。

### 4.3 操作按钮

#### 立即备份

- 作为主按钮。
- 点击后记录本次提醒已处理，然后跳转到 `/webdav-sync`。
- WebDAV 页面同时包含“导出全部数据”和 WebDAV 备份能力，因此不需要在弹窗中让用户提前选择备份方式。
- 跳转后不自动开始上传、导出或覆盖任何数据，避免未经确认的外部写入。

#### 我已了解

- 作为次按钮。
- 关闭弹窗并记录关闭时间。
- 只表示用户已看到提醒，不记录为“已经备份”。

#### 右上角关闭按钮与遮罩

- 右上角关闭按钮与“我已了解”行为一致。
- 点击遮罩可以关闭，行为同样视为本次提醒已读。
- 按 `Escape` 可以关闭。
- 关闭后恢复打开弹窗前的键盘焦点。

## 5. 触发规则

### 5.1 常规提醒

满足以下条件时显示常规提醒：

1. 当前路由不是 `/welcome`。
2. 当前没有版本更新弹窗或其他全屏弹窗。
3. 用户没有近期有效备份，或者暂时无法判断是否有近期备份。
4. 距离上次关闭备份提醒已经达到 30 天。

首次引入该功能时，如果不存在上次关闭时间，则在用户进入非欢迎页后显示。

### 5.2 已有备份时的抑制规则

以下任一时间在最近 30 天内，可视为存在近期备份，不显示常规提醒：

- 最近一次成功导出完整 JSON 的时间。
- 最近一次成功完成 WebDAV 备份或双向同步的时间。

仅仅配置了 WebDAV、勾选了自动同步开关，但从未成功同步，不应视为已有备份。

设置页现有的单独历史记录或音乐导出可以继续使用，但只有 WebDAV 页的“导出全部数据”作为完整备份时间。这样可以避免用户只导出音乐后，系统错误地认为历史记录已经得到保护。

### 5.3 存储风险提醒

以下情况视为存储风险：

- `checkStorageHealth()` 返回 `storageProtected === false`。
- 存储健康检查返回错误。
- 存在最近一次存储写入异常 `lastWarning`。

发生存储风险时：

- 可以忽略 30 天常规提醒间隔，立即提示用户备份。
- 持续存在但没有新异常事件的存储风险，采用 7 天提醒冷却时间。
- 同一浏览器页面会话中最多自动显示一次，避免用户关闭后切换路由时反复弹出。
- 如果同一条历史异常已经提醒过，后续启动时不应无限重复强提醒；需要保存最近已提醒的异常时间戳或异常标识。
- 文案可以在常规正文上方增加一行：“检测到当前存储保护状态异常，建议立即备份。”

### 5.4 与版本更新弹窗的顺序

现有 `UpdateNoticeModal` 也会在主布局中自动打开。两个弹窗不得叠加显示。

推荐顺序：

```text
进入主页面
    │
    ├─ 有未读版本更新 ──> 显示版本更新弹窗
    │                         │
    │                         └─ 关闭后等待约 300ms
    │
    └─ 无未读版本更新 ─────────────────────────┐
                                               │
                                               v
                                    判断是否显示备份提醒
```

协调规则：

- 版本更新弹窗优先显示。
- `UpdateNoticeModal` 需要向主布局报告打开和关闭状态。
- 版本更新弹窗关闭后，再执行备份提醒判断。
- 不使用固定的长时间延迟猜测版本弹窗是否已经关闭。

## 6. 状态与存储设计

所有状态键继续集中定义在 `utils/constants.ts`，所有读写继续使用 `getStorageValue()` 和 `setStorageValue()`。

建议新增：

```ts
export const BACKUP_REMINDER_LAST_DISMISSED_AT = "backupReminderLastDismissedAt";
export const BACKUP_LAST_EXPORT_AT = "backupLastExportAt";
export const BACKUP_LAST_RISK_WARNING_AT = "backupLastRiskWarningAt";
```

字段说明：

| 字段                                | 类型     | 含义                               |
| ----------------------------------- | -------- | ---------------------------------- |
| `BACKUP_REMINDER_LAST_DISMISSED_AT` | `number` | 最近一次关闭或确认提醒的时间       |
| `BACKUP_LAST_EXPORT_AT`             | `number` | 最近一次成功导出完整 JSON 的时间   |
| `BACKUP_LAST_RISK_WARNING_AT`       | `number` | 最近一次已提示的存储异常时间或标识 |
| 现有 `WEBDAV_LAST_SYNC`             | `number` | 最近一次成功 WebDAV 同步的时间     |

不新增 IndexedDB store，不修改任何业务数据结构。

### 6.1 备份时间计算

```ts
const latestBackupAt = Math.max(backupLastExportAt ?? 0, webDavLastSyncAt ?? 0);
const hasRecentBackup = Date.now() - latestBackupAt < 30 * 24 * 60 * 60 * 1000;
```

只有操作真正成功后才能更新时间：

- 导出过程中抛出异常时不更新 `BACKUP_LAST_EXPORT_AT`。
- WebDAV 上传、双向同步或自动同步失败时不更新 `WEBDAV_LAST_SYNC`。
- 点击“立即备份”只更新提醒处理时间，不更新备份成功时间。

## 7. 组件状态模型

建议由主布局统一协调自动弹窗，备份弹窗本身只负责展示和操作。

```ts
type BackupReminderReason = "routine" | "storage-risk";

interface DataBackupReminderModalProps {
  open: boolean;
  reason: BackupReminderReason;
  onClose: () => void;
  onBackup: () => void;
}
```

主布局需要掌握：

```ts
const [isUpdateNoticeOpen, setIsUpdateNoticeOpen] = useState(false);
const [isBackupReminderOpen, setIsBackupReminderOpen] = useState(false);
const [backupReminderReason, setBackupReminderReason] = useState<BackupReminderReason>("routine");
```

状态转换：

```text
初始化
  ├─ 欢迎页 ------------------------------> 不显示
  ├─ 版本更新未读 ------------------------> 更新弹窗
  │                                           └─ 关闭 -> 判断备份提醒
  └─ 无版本更新 --------------------------> 判断备份提醒

判断备份提醒
  ├─ 存储风险且本会话未提示 -------------> storage-risk
  ├─ 无近期备份且提醒间隔已到 ------------> routine
  └─ 其他 --------------------------------> 不显示

routine/storage-risk
  ├─ 立即备份 -> 记录关闭时间 -> 跳转 WebDAV
  └─ 关闭/我已了解 -> 记录关闭时间 -> 关闭
```

- 单独导出历史记录是否足以视为完成备份。

## 9. 视觉与无障碍要求

- 视觉风格与 `HistorySyncModal` 保持一致：全屏半透明遮罩、圆角卡片、明暗主题。
- 弹窗最大宽度建议为 `max-w-lg`，移动端保留左右边距。
- 使用 `lucide-react` 的 `ShieldAlert`、`TriangleAlert` 或 `DatabaseBackup` 图标。
- 主按钮使用项目现有蓝色或粉色；风险说明使用琥珀色。
- 只有检测到明确存储异常时才使用少量红色错误文案。
- 弹窗容器添加 `role="dialog"`、`aria-modal="true"` 和 `aria-labelledby`。
- 关闭按钮必须有可读的 `aria-label`。
- 键盘焦点不能移动到遮罩后的页面。
- 所有操作必须使用原生 `<button>`，并保留清晰的焦点样式。

## 10. 异常与边界处理

### 10.1 状态读取失败

- 无法读取提醒时间时，按“尚未提醒”处理，但只在当前会话显示一次。
- 无法读取备份时间时，不宣称用户没有备份，只显示常规风险文案。
- 状态读取错误写入控制台，不阻塞主页面渲染。

### 10.2 状态写入失败

- 关闭提醒时即使保存失败，也应允许用户继续使用页面。
- 当前会话内保存一个内存标志，防止用户切换路由后立即再次看到弹窗。
- 下一次重新打开扩展时可能再次提醒，这是可接受的降级行为。

### 10.3 跳转失败或路由变化

- “立即备份”先关闭弹窗，再执行路由跳转。
- 如果用户本来就在 `/webdav-sync`，只关闭弹窗，不重复导航。
- 跳转不应自动触发文件下载或 WebDAV 上传。

### 10.4 存储已被清理

提醒状态本身保存在 `browser.storage.local`。如果浏览器连同这些状态一起清理，扩展会把用户视为首次使用并重新显示提醒。这符合安全预期。

## 11. 验收标准

### 11.1 常规显示

- 首次进入 `/` 时显示备份提醒。
- `/welcome` 不显示提醒。
- 点击“我已了解”、关闭按钮、遮罩或按 `Escape` 都能关闭。
- 关闭后 30 天内不再显示常规提醒。
- 30 天后再次进入主页面会重新显示。

### 11.2 备份入口

- 点击“立即备份”后跳转到 `/webdav-sync`。
- 跳转不会自动执行上传、下载、导出或覆盖操作。
- 完整 JSON 导出成功后记录最新导出时间。
- 最近 30 天完成过完整导出或 WebDAV 同步时不显示常规提醒。

### 11.3 存储风险

- `storageProtected === false` 时显示存储风险版本文案。
- 存储健康检查存在错误或写入异常时显示风险提醒。
- 风险提醒在同一页面会话中最多自动显示一次。
- 用户关闭后切换路由不会立即重复显示。

### 11.4 弹窗协调

- 有未读版本更新时先显示版本更新弹窗。
- 版本更新弹窗和备份提醒不会同时出现。
- 关闭版本更新弹窗后，符合条件时再显示备份提醒。
- 欢迎页切换到主页面后才开始判断提醒。

### 11.5 视觉与键盘

- 明暗主题下文字、边框和按钮对比度正常。
- 窄屏下弹窗不超出视口，正文可以正常滚动。
- 打开弹窗后焦点进入弹窗。
- `Tab` 和 `Shift+Tab` 不会把焦点移到弹窗背后的页面。
- 关闭后焦点恢复到打开弹窗前的元素。

pnpm compile

- Chrome/Edge 明暗主题。
- 首次安装、已读版本更新、未读版本更新三种状态。
- 无备份、近期手动导出、近期 WebDAV 同步三种状态。
- 正常存储、未保护存储、存储检查异常三种状态。
- 鼠标、键盘和窄屏布局。

## 13. 实施建议

建议按以下顺序实现：

1. 增加状态常量和完整导出成功时间记录。
2. 为 `UpdateNoticeModal` 增加状态回调。
3. 新增 `DataBackupReminderModal` 及无障碍交互。
4. 在 `MainLayout` 中实现弹窗调度和路由跳转。
5. 补充类型检查、格式检查和手工验收。

本功能是数据安全提示的最后一道防线，不能替代历史记录丢失原因的诊断、删除保护、数据库健康检查和可靠备份机制。
